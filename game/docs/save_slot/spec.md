# spec.md — save_slot (E4)

Источник истины одного слота на диске.
Программа: [`docs/program/spec.md`](../../../docs/program/spec.md) этап E4.
Инвариант пути сохранения в [`game/AGENTS.md`](../../AGENTS.md) этот контур заменяет: диск есть, один файл.

## Цель

После нового запуска квартира помнит мета-состояние прошлого захода: дверь за кухней, выбранную находку на следующую попытку, последнюю строку ЖЭКа и `/pod/`.

## Граница

### Входит

- Один файл `user://slot.json`
- Поле `version`. В этом контуре версия `1`. Следующий контур борды поднимает запись до `2` и читает целый файл `1`: [`../imageboard/spec.md`](../imageboard/spec.md)
- Запись, когда сцена квартиры готова, и при закрытии окна
- Чтение один раз при входе `GameState` в дерево, до `_ready` квартиры
- Явная функция миграции: версия `1` остаётся как есть; любая другая не читается
- Битый файл → новая игра и бытовая строка. Другие файлы в `user://` не открываются и не стираются

### Не входит

- Облако, несколько слотов, шифрование
- Запись середины этажа: текущий этаж, HP, убийства этого забега, находки этажа, seed
- Продолжение забега с места обрыва
- Wipe чужих файлов

## Поведение

1. Нет файла — новая игра. Строка ЖЭКа и `/pod/` — те, что и раньше у пустого `GameState`. Это не ошибка.
2. Файл версии `1` со всеми ключами ниже — поля памяти становятся полями файла.
3. Не JSON, не объект, версия не `1`, нет ключа, не тот тип или значение вне списка — чтение не удаётся. Память этого экземпляра становится новой игрой, а `zh_ek_notice` — строка «Папка с документами не читается. Завели новую карточку жильца.» Файл слота при неудачном чтении не пишется и не удаляется. JSON-число для `version`, `last_kills` и `last_floors` годится и как int, и как float без дробной части: Godot читает число из JSON как float. Ненулевая дробная часть — порча. Запись кладёт целые.
4. Квартира в `_ready` сначала показывает уже прочитанное, потом записывает слот. Запись идёт только в `user://slot.json`. Если чтение было порчей, эта запись заменяет битые байты уже годным файлом версии 1, и бытовая строка лежит в нём как обычный `zh_ek_notice`. SV2 квартиру не открывает, поэтому в самом SV2 битые байты ещё на месте. Копия по другому пути не затрагивается ни чтением, ни этой записью.
5. Закрытие окна вызывает ту же запись. В память попадают только ключи слота, не живой этаж.
6. `finish_extract` / `finish_death` по-прежнему обновляют `last_result`, счётчики и тексты ЖЭКа в памяти. На диск это попадает записью квартиры или закрытием окна, не отдельным форматом.
7. Выбор boon на экране результата остаётся в `pending_boon`. Квартира после «вернуться домой» уже видит его и записывает.

Ключи версии 1:

| Ключ | Тип | Допустимо |
|---|---|---|
| version | int | только 1 |
| pending_boon | string | `none`, `damage`, `maxhp`, `speed` |
| active_boon | string | те же четыре |
| extracted_once | bool | |
| kitchen_door_unlocked | bool | |
| last_result | string | пустая строка, `death`, `extract` |
| last_kills | int | ≥ 0 |
| last_floors | int | ≥ 0 |
| zh_ek_notice | string | |
| board_feed | string | |

Чужие ключи в файле версии 1 игнорируются и при записи не возвращаются. Это не миграция. Новый ключ следующих этапов требует новой версии и ветки в функции миграции.

## User paths

| Путь | Актор | Успех | Ошибка |
|---|---|---|---|
| SV1 Запись и новый экземпляр | Смоук | Флаг записан → второй объект `GameState` читает тот же флаг с диска | Флаг остался только в памяти первого |
| SV2 Битый файл | Смоук | Копия целого слота сделана до порчи. Чтение порчи даёт новую игру и бытовую строку. Байты копии те же | Копия исчезла или укоротилась |
| SV3 Нет файла | Смоук | Чтение не ставит бытовую строку порчи | Пустой каталог считается поломкой |

## Платформы

- PC: Windows — must. Путь `user://`, не абсолютный диск
- Mobile: later, тот же `user://`
- Расхождения до E11: нет

## Контракты снаружи

- Пишет и читает только `user://slot.json`
- `GameState._ready` читает. Квартира после показа пишет. `NOTIFICATION_WM_CLOSE_REQUEST` пишет
- Прежние смоуки (`full`, `loop`, `combat_feel`, `builds`, `floors`) в начале прогона сбрасывают мета-поля хаба к новой игре и удаляют `user://slot.json`. Иначе уже прочитанный слот ломает их: `last_result` или `pending_boon` приходят с диска. Это обязанность смоуков, не отмена чтения в игре
- Версия слота в этом контуре: `1`

## Delta — E5 борда

Живой контракт версии: [`../imageboard/spec.md`](../imageboard/spec.md).

Запись становится версией `2` и добавляет `lead_id`. Целый файл версии `1` читается миграцией, это не порча из п.3. Порчей остаётся не JSON, не хватает ключей своей версии, версия не `1` и не `2`.
