| C1 | Выбор открывается до боя, физика стоит, так что на этом этаже раниться и потом лечиться нельзя. Новый `go_run` ставит HP равным максимуму до этажа. `tap_water` даёт +30 HP и прямо запрещает превысить максимум, поэтому на первом этаже (и на любом следующем, куда игрок вошёл уже полным) текущее HP не меняется. Успех RB1 требует, чтобы стат этой id уже был другим; ошибка пути — «стат прежний». Headless в границе спеки тоже требует, что выбор меняет обещанный стат. Для id `tap_water` этот путь из текста не принять. | да | open |
| C2 | `sweater` обещает и +25 к максимуму, и +25 HP сейчас. Потолок «не выше максимума» написан только у `tap_water`. Если текущее прибавлять к старому максимуму, на полном HP прибавка сейчас равна нулю и остаётся только максимум. Чтение «сначала новый максимум, потом +25 текущего, не выше него» оба числа выполняет. Это не второе противоречие строк, путь RB1 для максимума HP всё равно виден. | нет | open |
