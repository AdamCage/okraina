# Принципы разработки игр на Godot

Зачем приняты инварианты из [AGENTS.md](AGENTS.md). Если принцип мешает
конкретному случаю — зафиксировать исключение в проектном `AGENTS.md`,
а не молча обойти.

## 1. Игра доказывается игрой

Спека без playable path оставляет агента и ревьюера без факта.
Vertical slice и user paths в Godot editor / export — дешёвый способ
поймать дыру до store.

## 2. Дизайн — контракт, не роман

Элаборация нужна, чтобы реализация не гадала. Лишние главы GDD
расходятся с кодом. Срезы из [design.md](design.md) пишут по вопросу.

## 3. Scope — первая механика качества

Бесконечный backlog внутри одного PR ломает ревью и релиз.
Out-of-scope явно; новый аппетит — новый Issue/класс.

## 4. Платформа не «потом»

Input, lifecycle (background/resume), safe area, performance,
export presets, store rules различаются. Скрытое «на Android потом»
= скрытый долг и сорванный release.

## 5. Godot — канон движка

Канон учит процессу и инвариантам **на Godot**. Версия Godot и
опциональный C# — факты проекта. Смена движка — проектное решение
с гейтом, не «агент знает лучше».

## 6. Данные балансируют, код исполняет

Магические числа в ветках усложняют патч и A/B. Если проект завёл
ресурсы/таблицы — новый параметр = поле ресурса + пример + строка в доке.

## 7. Сохранения священны

Игрок доверяет прогрессу. Миграция схемы save (`user://` и формат) —
контракт. Wipe «чтобы проще» — гейт человека и запись в release/incident.

## 8. Бюджет перфоманса — часть DoD

Красивая фича на целевом device с 15 fps — дефект. Budget из
проектного `AGENTS.md` / [platforms.md](platforms.md). Profiler —
источник факта.

## 9. Наблюдаемость для крашей

Билд без понятного crash signature / логов / build id нельзя чинить.
Стабильные имена сцен/нод/autoload и идентификатор билда обязательны.

## 10. Специализация сужает

Проект может запретить конкретный паттерн (например C#, определённый
addon). Проект не может молча заменить процесс канона «потому что так
быстрее набросать сцену».
