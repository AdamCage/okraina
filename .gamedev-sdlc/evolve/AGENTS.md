# AGENTS.md — эволюция канона

Домен для агентов, которые меняют **этот** репозиторий.
Потребитель `<sdlc-root>` файл не читает, пока не контрибьютит.

Процесс тот же: сначала
[../process/workflows/router.md](../process/workflows/router.md),
потом рецепт здесь. Домен не заменяет process.

Читать вместе с [SKILL.md](SKILL.md).

## Когда применять

Любое изменение `process/`, `evolve/`, доменных канонов (`game/`
и следующих), корневых `README.md` / `AGENTS.md`, шаблонов,
skill/rule, `.github/` этого репозитория.

## Когда не применять

- Продуктовый код в другом репозитории.
- Потребитель только *читает* канон.
- Правка чужой игры, ассетов, store listing.

## Порядок чтения

1. [../AGENTS.md](../AGENTS.md) — факты этого репо.
2. [../process/AGENTS.md](../process/AGENTS.md) и router.
3. Этот файл.
4. Строка в [SKILL.md](SKILL.md).
5. Если задет предметный домен — его `AGENTS.md` / `SKILL.md`.

## Hard invariants

1. Две аудитории: агент здесь и агент потребителя через
   `<sdlc-root>/...`. Продуктовых имён в каноне нет.
2. Новый домен не пишет второй SDLC. Форма — как у
   [../game/](../game/). Каркас: [templates/domain/](templates/domain/).
3. Новый подход (класс, роль, гейт, тип артефакта, правило конфликта)
   = `feature-cycle`, не правка мимоходом.
4. Улучшение существующего текста = `increment`. Соседей не переписывать.
5. В канон — только то, что верно для следующего проекта.
6. Входные пути стабильны. Переименование в одном изменении правит
   `README.md`, `process/workflows/bootstrap-project.md` и
   `specialize.md` задетых доменов.
7. Нет копий между process и доменом. Шаблоны остаются плейсхолдерами.
8. Один путь на документ. Второго дерева нет (никакого `.common`).
9. Новый тип артефакта — строка в
   [../process/artifacts.md](../process/artifacts.md) и правило по классам.
10. Спросить до удаления домена, смены правил конфликта или ломающего
    переименования входа.
11. GitHub SoR этого репо: Issue/PR на изменение канона; labels из
    `.github/labels.yml`; release канона — только по просьбе.
