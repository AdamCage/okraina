# Ревью изменений канона

Сначала [../process/review.md](../process/review.md), затем этот список.
Ревьюер — новый контекст, тот же diff не патчит.

## Блокеры

- [ ] В каноне нет продуктовых имён (конкретная игра, bundle id, store
      listing, команда прода чужого репо).
- [ ] Домен не пересказал SDLC (роли, эскалация, router, гейты process).
- [ ] Новый подход имеет строку в router и/или `process/SKILL.md`,
      правило в `artifacts.md`, стык в `specialize.md` / `github.md` если нужно.
- [ ] У документа один путь. Нет второго дерева и нет ссылок на `.common`.
- [ ] Шаблон не заполнен фактами репозитория или продукта.
- [ ] В проектный шаблон `process/templates/AGENTS.project.md` не
      скопирован process.
- [ ] SKILL-таблица есть и строки совпадают с фактическими файлами.
- [ ] Ломающее переименование правит README и bootstrap (и specialize
      доменов) в том же изменении; человек гейт прошёл.
- [ ] У нового домена заполнены «когда применять» и «когда не применять».
- [ ] Каталог домена в корне репо, не под `process/`, не под `domains/`.
- [ ] `.github/` labels/templates ссылаются на существующие классы router.

## Should

- [ ] Стык домена с process указан в доменном `SKILL.md` (2–3 строки).
- [ ] increment не переписал соседние разделы.
- [ ] Примеры в домене — плейсхолдеры (`<feature_id>`), не живые имена.

## Ниты

Стиль, плотность, порядок пунктов. После первого прохода не блокируют.

## Проверка потребителя

Если задет вход или bootstrap: dry-run
[../process/workflows/bootstrap-project.md](../process/workflows/bootstrap-project.md)
на вымышленном репо. Ожидание: тонкий `AGENTS.md`, ссылки, нет копипасты.
