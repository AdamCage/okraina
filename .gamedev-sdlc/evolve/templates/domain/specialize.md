# Как специализировать `<domain>` под проект

`<sdlc-root>/<domain>` задаёт подход. Репозиторий добавляет факты:
пути, имена, локальные запреты.

Не копировать принципы и рецепты. Ссылка на
`<sdlc-root>/<domain>/AGENTS.md`.

## Что писать в проектном `AGENTS.md`

Шаблон: [templates/AGENTS.project.md](templates/AGENTS.project.md).

Обязательно:

- ссылка на `<sdlc-root>/<domain>/AGENTS.md`;
- список контуров / модулей / платформ этого домена;
- локальные инварианты;
- команды точечной проверки.

## Новый репозиторий

Сначала `<sdlc-root>/process/workflows/bootstrap-project.md`,
потом этот файл. Не править канон под один контур.

## Когда расширять канон

Только то, что верно для следующего проекта с этим доменом.
Подъём — `<sdlc-root>/evolve/`, не правка vendor-копии.
