# Рецепты эволюции

Класс — из [../process/workflows/router.md](../process/workflows/router.md).
Ниже — *как* менять этот репозиторий. Каталог домена — корень репо,
рядом с `game/`. Не под `process/`. Не под `domains/`.

Имена файлов в спеке — плейсхолдеры до выбора. Продуктовых имён нет.

## new-domain

Класс: `feature-cycle`.

1. Спека: когда применять / **когда нет**, инварианты, какие классы
   process зовут домен, чего домен не пересказывает.
2. Критик: нет второго SDLC, нет продуктовых имён, есть «когда нет».
3. Скопировать [templates/domain/](templates/domain/) в
   `<sdlc-root>/<domain>/`. Заполнить инварианты. Таблица в `SKILL.md`.
4. Строка в [../README.md](../README.md) (состав) и в
   [../process/workflows/bootstrap-project.md](../process/workflows/bootstrap-project.md)
   (шаг «известные домены»).
5. Если нужен editor skill — тонкий указатель, не копия текстов.
6. Проверка: dry-run bootstrap на вымышленном репо; следующая задача
   про этот домен попадает в router → `<domain>/SKILL.md`.
7. Issue/PR по [../process/github.md](../process/github.md).
8. Ревью по [review.md](review.md).

Не класть домен, который неверен для следующего проекта.
Сначала кандидат в продукте — см. `lift-from-project`.

## new-approach

Класс: `feature-cycle`.

Новый класс задач, роль, гейт, тип артефакта, правило конфликта
или изменение GitHub SoR-контракта канона.

1. Спека: зачем существующего набора мало; как выглядит строка router;
   какие классы требуют новый артефакт.
2. Критик. Human gate, если трогаем конфликт или hard invariants process.
3. Правки одним контуром: router, `process/SKILL.md`, `artifacts.md`,
   роль если новая, шаблон если новый тип, `specialize.md` /
   `github.md` если меняется конфликт или SoR. Домены — только стык.
4. Не оставлять второй путь «по-старому» без явного deprecation
   в том же изменении.
5. Проверка: у router есть строка; у SKILL — строка; у артефакта —
   правило по классам; labels/templates согласованы, если задет GitHub.
6. Ревью. Release — только по просьбе.

## improve-existing

Класс: `increment`.

Формулировка, дыра в чеклисте, битая ссылка, уточнение инварианта
без смены смысла.

1. Дельта: какой файл и какой обещание уточняется. Соседей не трогать.
2. Критик — если меняется смысл инварианта. Иначе можно без него.
3. Правка. Живые ссылки. Не заполнять шаблоны фактами.
4. Ревью дельты. Ниты не держат.

Переписать тон соседнего раздела — не increment, резать задачу.

## lift-from-project

Класс: сначала `spec-only`, затем `increment` или `feature-cycle`.

1. Выписать паттерн без имён продукта: что повторилось, для кого верно.
2. Спека: это новый домен, новый подход или абзац в существующем файле?
3. Критик: фильтр «верно для следующего проекта».
4. Если нет — оставить в продукте, в канон не тащить.
5. Если да — `new-domain` / `new-approach` / `improve-existing`
   по выбранному типу. Не копировать проектный `AGENTS.md` целиком.

## breaking-entry-change

Класс: `feature-cycle`. Гейт человека обязателен
([AGENTS.md](AGENTS.md) п. 10, [../AGENTS.md](../AGENTS.md)).

Ломает уже прописанные в продуктах пути: переименование `README`,
`process/AGENTS.md`, `router.md`, `*/SKILL.md`, `*/specialize.md`,
удаление домена, смена правил конфликта.

1. Спросить. Нет ответа — стоп.
2. Спека: старый путь → новый, кто чинит потребителя, есть ли окно
   совместимости. Канон не держит два дерева (инвариант 8): либо
   одно изменение с явной пометкой в README, либо не делать.
3. В том же diff: [../README.md](../README.md),
   [../process/workflows/bootstrap-project.md](../process/workflows/bootstrap-project.md),
   `specialize.md` задетых доменов, корневой [../AGENTS.md](../AGENTS.md)
   если меняются входы этого репо. Grep по репо на старый путь.
4. Проверка: dry-run bootstrap; нет ссылок на старый путь.
5. Ревью. Тег/release — по просьбе: потребители должны увидеть слом.

## Чего не делать в рецептах

- Не править `game/principles.md` «под процесс» — стык живёт
  в `game/SKILL.md` и specialize.
- Не создавать `.common` или `domains/`.
- Не заполнять [templates/domain/](templates/domain/) фактами
  будущего домена — копируют каркас, заполняют уже в `<domain>/`.
