# Артефакты

Что писать, какой класс требует, живое или одноразовое.
Шаблоны — [templates/](templates/AGENTS.project.md). Диаграммы —
меню, не полный комплект. Раннер E2E / playtest — факт проекта, не канона.

E2E в каноне = приёмочные сценарии из user paths + отчёт о прогоне
(включая playtest на устройстве, если класс и проект это требуют).
Не «поднять автотесты, потому что так правильно».

## Меню

| Артефакт | Живой? | Кто пишет | Зачем |
|---|---|---|---|
| `spec.md` | Да | аналитик | Контракт поведения. Источник истины |
| `assumptions.md` | Да, пока открыты | аналитик | Неблокерные вопросы и принятые допущения |
| C4 context/container | Пока держит контракт | аналитик | Границы системы, не внутренности кода |
| network | Пока держит контракт | аналитик | Узлы, порты, доверие (онлайн-сервисы) |
| sequence | Пока держит контракт | аналитик | Вызовы между участниками на путь игрока |
| flowchart | Пока держит контракт | аналитик | Ветвления решения, не дубль кода |
| user paths | Да, вместе со спекой | аналитик | Сценарии приёмки, E2E, playtest |
| доменный дизайн-пакет | Да | аналитик (+ домен) | GDD-фрагмент, lore, systems, UX, tech design, scope — см. [../game/design.md](../game/design.md) |
| доменный `ARCHITECTURE.md` | Да | implementer | Раскладка *этого* контура в домене |
| `review.md` | На цикл | ревьюер / критик | Проблемы, риски, пробелы, приоритет, статус |
| `test-report.md` | На цикл / прогон | tester | Что гоняли, playtest, что красное, что намеренно не гоняли |
| `release.md` | На поставку | releaser | Что вышло, PC/mobile пути, как откатить |
| GitHub Issue / PR | На цикл | все роли | SoR: ссылки на артефакты, labels, milestone |

Живой = меняется вместе с кодом или контрактом в том же изменении.
Одноразовый = фиксирует проход (ревью, прогон, поставка). Старые
проходы не вычищать молча, если на них ссылаются.

## Что обязательно по классу

| Класс | Обязательно | По необходимости | Не делать |
|---|---|---|---|
| `bootstrap-project` | корневой `AGENTS.md` из шаблона, GitHub labels/templates по [github.md](github.md) | skill/rule редактора | Спека продукта, диаграммы |
| `spec-only` | `spec.md`, `assumptions.md`, Issue со ссылками | 1–2 диаграммы, user paths, дизайн-пакет | Код, `release.md` |
| `feature-cycle` | `spec.md`, `assumptions.md`, user paths, дизайн-пакет (если новый игровой контур), `test-report.md`, `review.md`, PR | диаграммы, доменный `ARCHITECTURE.md` | `release.md` без просьбы ship |
| `increment` | дельта в `spec.md` (или явный «без дельты контракта»), `test-report.md`, `review.md`, PR | `assumptions.md`, дельта дизайна, `ARCHITECTURE.md` | Полный набор диаграмм «как у большой фичи» |
| `hotfix` | repro в `test-report.md` или шаги в `review.md`, регрессия, Issue/PR | дельта `spec.md`, если меняется обещание | Новые user paths «заодно» |
| `review-only` | `review.md`, комментарии в PR | чтение существующей спеки / дизайна | Патч того же diff-а |
| `incident` | таймлайн и impact в `review.md` или отчёте инцидента, Issue | hotfix-артефакты, если чиним код | Тихий рефакторинг рядом |
| `deploy` | запись в `test-report.md` или лог «что выкатили / как проверили» | — | Новая спека |
| `admin` | краткое «что и зачем» в коммите / PR | `review.md`, если трогает чужие входы | Продуктовая спека |
| `release` | `release.md`, GitHub Release/tag | ссылка на `test-report.md` цикла | Новые фичи в том же diff-е |

## Диаграммы: меню, не набор

Аналитик выбирает *зачем* картинка, не генерирует все.

| Нужно понять | Берём |
|---|---|
| Кто с кем и зачем | C4 context, иногда container |
| Как пакеты/сервисы/сцены стыкуются | C4 container / доменная схема |
| Кто ходит по сети | network |
| Порядок на путь игрока | sequence |
| Ветки решения / FSM | flowchart |

Нет вопроса — нет диаграммы. Полный комплект «чтобы было» запрещён.

## User paths и E2E / playtest

1. Путь = актор (игрок / система) → цель → шаги → ожидаемый результат → ошибка.
2. Сценарий приёмки ссылается на путь, не выдумывает другой сюжет.
3. Команда запуска / устройство / editor mode — строка в корневом `AGENTS.md`.
4. Если раннера нет — в `test-report.md` явно: «E2E/playtest не гонялись, …»,
   и это не дыра *канона*. Дыра проекта, если проект обещал раннер.
