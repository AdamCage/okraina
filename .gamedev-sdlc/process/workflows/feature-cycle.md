# feature-cycle — новый контур

Полный цикл. Брать, когда нет живой спеки на этот контур или меняется
подход (новый путь игрока, новая механика, новый тип артефакта
в каноне). Дельта к живому контуру — [increment.md](increment.md).
Поставка — отдельный класс [release.md](release.md), только если
человек попросил ship/версию.

Артефакты: [../artifacts.md](../artifacts.md).
Гейты: [../gates.md](../gates.md).
GitHub: [../github.md](../github.md).

Карта стадий: анализ → элаборация → разработка → запуск/отладка →
ревью → фиксы/повтор → (отдельный) release.

## 0. Учёт

1. Создать или найти GitHub Issue. Labels: класс, платформа, тип.
2. Ветку назвать по принятому в проекте шаблону; связать с Issue.

## 1. Анализ

Роль: [../roles/analyst.md](../roles/analyst.md).

1. Прочитать корневой `AGENTS.md` и доменный `AGENTS.md`. Не угадывать пути.
2. Собрать **только блокирующие** вопросы. За ход — потолок 5–7.
   Остальное — в `assumptions.md`, статус `open` / `accepted` / `rejected`.
3. Диаграммы — из меню [../artifacts.md](../artifacts.md), не полный набор.
4. Записать user paths: актор, цель, шаги, успех, ошибка.
5. `spec.md` — источник истины поведения. Чат после записи не расширяет контракт.
6. Issue обновлён ссылками на артефакты; label `stage:analysis`.

Стоп, если остались открытые блокеры. Не писать код.

## 2. Элаборация и критик аналитики

Роль аналитика продолжает дизайн-пакет домена
([../../game/design.md](../../game/design.md), рецепт «Элаборация» в
[../../game/workflows.md](../../game/workflows.md)): game design, lore,
systems, UX, technical design, scope — **только то, без чего контракт
невыполним**. Не полный альбом «на всякий случай».

Роль критика: [../roles/critic.md](../roles/critic.md). **Новый** субагент.

1. Вход: `spec.md`, `assumptions.md`, дизайн-пакет, диаграммы, user paths.
   Не история аналитика.
2. Ищет дыры контракта, скрытые допущения, невыполняемые пути,
   конфликт с hard invariants, платформенные дыры (PC vs mobile),
   раздутый scope.
3. Пишет замечания в `review.md` секции analytics **или** списком
   в `assumptions.md`. Не переписывает спеку/дизайн за аналитика.
4. Human gate: человек закрывает блокеры ответами **или** явно принимает
   допущения. Пока гейт не снят — шага 3 нет.
5. Label Issue: `stage:elaboration`.

Аналитик правит. Критик не становится implementer-ом в том же контексте.

## 3. Разработка

Роль: [../roles/implementer.md](../roles/implementer.md).
Доменные рецепты — после класса, из `<domain>/SKILL.md`.

1. Код по контракту. Не шире спеки. «Заодно» — в `assumptions.md`, не в diff.
2. Дельта документации: спека, дизайн (если поведение изменили),
   доменный `ARCHITECTURE.md`.
3. Пирамида:
   - unit / integration на новую логику;
   - E2E / playable paths **из user paths**;
   - раннер / устройство — строка проектного `AGENTS.md`. Нет раннера —
     явная запись в `test-report.md`.
4. Draft PR с ссылкой на Issue. Label `stage:dev`.
5. Несколько агентов-implementer — **только** если в спеке независимые куски.
   Иначе один.

## 4. Запуск и отладка

Роль: [../roles/tester.md](../roles/tester.md). Может быть тот же
контекст, что implementer, если красное поймали сразу; отдельный
субагент — если просят независимый прогон / playtest.

1. Собрать playable build по командам проекта (editor / CI artifact).
2. Красное / краш чинить. Не переносить в «known issues» без accept.
3. Playtest гоняет пути из спеки. Запись — `test-report.md`.
4. Доменный debug: [../../game/workflows.md](../../game/workflows.md).
5. Label: `stage:playtest`. Локальный `deploy` на device/track —
   только если попросили или проект так описал для этого класса.

## 5. Цикл ревью

Роль: [../roles/reviewer.md](../roles/reviewer.md). Новый контекст.
Процедура: [../review.md](../review.md). Домен: [../../game/review.md](../../game/review.md).

1. Ready for review. Ревьюер пишет `review.md` + PR comments.
2. Выход — `blocker = 0`.
3. Итераций > 5 при живых блокерах → человек, дедлок одним абзацем.
4. Label: `stage:review`.

## 6. Фиксы по ревью

1. Implementer закрывает пункты. Tester перегоняет затронутое.
2. Ревьюер на следующем проходе **не** открывает новый вкус.
3. Вернуться к шагу 5, пока блокеры не ноль или эскалация.
4. Merge по branch protection, когда blocker = 0 и checks green.

## 7. Release

Не часть этого рецепта. Если человек сказал «выпусти / поставь тег /
сделай release / отправь в store» — сменить класс на [release.md](release.md).
Иначе остановиться на зелёном цикле и нуле блокеров.

## Чего не делать

- Не стартовать шаг 3 из того же контекста, что не прошёл шаг 2.
- Не писать полный комплект C4 / полный GDD «потому что так солидно».
- Не звать второго implementer-а на один контракт.
- Не считать ревью пройденным по устному «lgtm» без `review.md`,
  если класс требует артефакт.
- Не merge в обход required checks без гейта человека.
