# deploy — выкатить уже собранное

Выкат существующего артефакта (playable build, internal track,
TestFlight / Play internal, Steam branch). Не место для фич и хотфиксов.
Нет явной просьбы выкатить — класс не брать.

Если класс выключен — стоп.

## Шаги

1. **Что выкатываем.**
   Коммит / тег / CI artifact / build number. Откуда взяли.
   Куда (какая среда / track / устройство). Цель — одна среда за раз,
   если проект не описал конвейер.

2. **Гейт.**
   Production / store public — спросить всегда. Internal — как в
   проектном `AGENTS.md`. [../gates.md](../gates.md).

3. **Предусловия.**
   Команды проверки перед выкатом — из проектного `AGENTS.md`
   (smoke, crash-free boot, platform checklist).
   Результат — в `test-report.md` или в комментарии PR/Issue.

4. **Выкат.**
   Только команды проекта (`gh`, store CLI, CI job). Не изобретать
   upload, если его нет в обвязке. Секреты не печатать.

5. **Проверка после.**
   Spot-check из проектного `AGENTS.md`. Успех — заранее,
   не «ну вроде запустилось».

6. **Откат.**
   Если сломалось: остановиться. Откат — деструкция, спросить,
   если проект не задал автоматический rollback. Не чинить live
   новым feature-diff-ом под видом deploy.

7. **Запись.**
   Comment в Issue/PR: артефакт, среда, результат. GitHub Environment
   deployment — если проект завёл.

## Артефакты

Запись «что / куда / команда / результат». `release.md` не заменяет
deploy: версия могла выйти раньше. Новый `spec.md` не нужен.

## Чего не делать

- Не смешивать с `release` без просьбы на оба.
- Не катить из грязного рабочего дерева «потому что успеет».
- Не подписывать чужим сертификатом «временно».
