# Router — классификация задачи

Первый шаг любой работы. На выходе — **один** класс и **один** рецепт.
Не запускать соседний рецепт «на всякий случай».

Сомнение → более узкий класс (`increment` вместо `feature-cycle`,
`review-only` вместо цикла, `spec-only` вместо кода).

## Классы

| Класс | Когда | Рецепт |
|---|---|---|
| `bootstrap-project` | В продукте ещё нет обвязки на `<sdlc-root>` | [bootstrap-project.md](bootstrap-project.md) |
| `spec-only` | Нужен контракт / элаборация без кода | [spec-only.md](spec-only.md) |
| `feature-cycle` | Новый контур, новая механика, новый путь игрока, новый подход | [feature-cycle.md](feature-cycle.md) |
| `increment` | Дельта к существующему контуру с живой спекой | [increment.md](increment.md) |
| `hotfix` | Сломано известное поведение, чиним узко | [hotfix.md](hotfix.md) |
| `review-only` | Просят разобрать diff / playtest-критику, не делать работу за автора | [review-only.md](review-only.md) |
| `incident` | Live / критичный стенд деградировал, сначала стабилизация | [incident.md](incident.md) |
| `deploy` | Выкатить уже собранное (build / internal track) | [deploy.md](deploy.md) |
| `admin` | CI, права, ignore, labels, branch protection, skill/rule | [admin.md](admin.md) |
| `release` | Явно просят ship / версию / тег / GitHub Release / store | [release.md](release.md) |

Если класс выключен в корневом `AGENTS.md` потребителя — не брать его.
Сказать, что выключен, и предложить ближайший включённый или стоп.

## Как выбрать

Идти сверху вниз, первое совпадение. Потом проверить, нет ли более узкого.

1. Канон в продукт ещё не подключён, просят обвязку → `bootstrap-project`.
2. Live/прод горит, игроки теряют прогресс или деньги → `incident`
   (после стабилизации код-фикс может стать `hotfix`).
3. Просят только выкатить существующую сборку → `deploy`.
4. Просят версию / тег / changelog / GitHub Release / store ship → `release`.
5. Просят только ревью PR/diff / critique дизайна без правок → `review-only`.
6. CI, права, хуки, labels, editor skill, массовый перенос без новой фичи → `admin`.
7. Просят только спеку / GDD-фрагмент / «как делать», без кода → `spec-only`.
8. Баг на уже обещанном поведении, узкий фикс → `hotfix`.
9. Есть живая спека, меняем кусок того же контура → `increment`.
10. Нового контура ещё нет, или меняется подход (новый класс/роль/гейт/
    тип артефакта / правило конфликта) → `feature-cycle`.

Опечатка, переименовать локальную переменную, поправить битую ссылку
в одном файле — не `feature-cycle`. Это `increment` или `admin`
(если трогает входные пути канона — см. [../../evolve/workflows.md](../../evolve/workflows.md)).

## Стык с доменом

Router **не** выбирает домен. Домен следует из файлов и корневого
`AGENTS.md` (список доменов).

После класса:

- продукт + game → `<sdlc-root>/game/SKILL.md`;
- этот репозиторий канона → `<sdlc-root>/evolve/SKILL.md`;
- неизвестный домен → [../new-domain.md](../new-domain.md).

## Стык с GitHub

После выбора класса — завести или обновить Issue/PR по
[../github.md](../github.md). Не начинать большой цикл без Issue.

## Чего не делать

- Не параллелить `feature-cycle` и `hotfix` на одном контуре.
- Не начинать `release`, потому что «фича готова» — человек должен попросить.
- Не называть класс в чате и работать по другому рецепту.
