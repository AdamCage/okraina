# admin — обвязка и хозяйство

CI, права, `.gitignore`, editor skill/rule, labels, branch protection,
массовые переносы без новой продуктовой фичи. Не админ: новый путь
игрока, новый домен в каноне, смена правил конфликта.

Смена входных путей **канона** — не admin, а evolve
`breaking-entry-change` ([../../evolve/workflows.md](../../evolve/workflows.md)).

## Шаги

1. **Назвать работу одним предложением.**
   «Повесить workflow build», «добавить label class:*»,
   «исключить `.env` / keystore». Если всплывает поведение игры —
   сменить класс.

2. **Гейт.**
   Права, секреты в CI, удаление веток, force-push, смена branch
   protection / Environments — спросить. [../gates.md](../gates.md).

3. **Сделать минимальный diff.**
   Один механизм за изменение. Не подмешивать рефакторинг игрового кода.
   GitHub-правки — по [../github.md](../github.md).

4. **Проверка.**
   Workflow зелёный, skill находится, ignore скрывает секрет,
   label создаётся, ссылка живая. Команды — из проектного
   `AGENTS.md` или из самого workflow-файла.

5. **Ревью.**
   Нужно, если правка влияет на других агентов или на вход канона
   в продукте (корневой `AGENTS.md`, skill, protection). Иначе
   достаточно понятного PR. Ревьюер не патчит.

## Артефакты

Спека не обязательна. Если меняется обещание «как агент стартует» —
строка в корневом `AGENTS.md` продукта, не копия process.
PR обязателен, если трогает `.github/` или обвязку агента.

## Чего не делать

- Не плодить Cursor-конфиг без существующего в репо паттерна.
- Не класть токены / keystore в workflow-файлы.
- Не использовать admin, чтобы обойти выключенный `deploy`.
- Не ослаблять branch protection «чтобы агент мог пушить в main».
