# spec-only — контракт без кода

Нужна граница работы и/или элаборация дизайна. Реализацию не просили.
Результат — живая спека (+ дизайн-пакет при игровом контуре),
не «подумали в чате».

Если после спеки человек сразу просит сделать — новый класс
(`feature-cycle` или `increment`), не продолжать молча в том же рецепте
без повторного router.

## Шаги

1. **Класс подтверждён.**
   Нет скрытого «ну и набросай код». Есть — вернуть в router.

2. **Issue.**
   Labels: `class:spec-only`, платформа, `stage:analysis` → `stage:elaboration`.

3. **Анализ.**
   Как шаг 1 [feature-cycle.md](feature-cycle.md):
   блокеры 5–7 за ход, остальное в `assumptions.md`,
   диаграммы из меню, user paths, `spec.md` — источник истины.

4. **Элаборация (если игровой контур).**
   Рецепт из [../../game/workflows.md](../../game/workflows.md) и
   [../../game/design.md](../../game/design.md): только необходимые
   срезы GDD/lore/systems/UX/tech/scope.

5. **Критик.**
   Новый субагент. Как шаг 2 feature-cycle.
   Human gate на блокеры или accepted assumptions.

6. **Правка спеки / дизайна.**
   Аналитик закрывает замечания критика. Не implementer.

7. **Стоп.**
   Готово, когда блокеров аналитики нет и человек не просил код.
   `test-report.md` не нужен. `review.md` — если критик писал туда;
   иначе достаточно чистой спеки, закрытых допущений и ссылок в Issue.

## Артефакты

Обязательны: `spec.md`, `assumptions.md`, Issue.
По необходимости: 1–2 диаграммы, user paths, дизайн-пакет.
Запрещены в этом классе: продуктовый код, `release.md`.

В **этом** репозитории канона аналитика — контракт для агентов
(что меняется в process/evolve/домене), не GDD чужой игры.

## Чего не делать

- Не заполнять шаблоны канона фактами продукта.
- Не плодить полный альбом диаграмм и полный GDD.
- Не принимать свои допущения без человека, если они блокеры.
