# increment — дельта к живому контуру

Короткий `feature-cycle`. Спека уже есть. Меняется кусок того же
контура, тот же путь игрока или узкое расширение.

Сомнение «это новый контур?» → [feature-cycle.md](feature-cycle.md).
Сломали обещанное и надо узко починить → [hotfix.md](hotfix.md).

## Шаги

1. **Найти живой контракт.**
   Путь к `spec.md` / дизайн-пакету / доменному `ARCHITECTURE.md` —
   из проектного `AGENTS.md` или из Issue. Нет живой спеки — это не increment.

2. **Issue / ветка / labels.**
   `class:increment`, платформа, связь с milestone при наличии.

3. **Дельта контракта.**
   Дописать в `spec.md` секцию дельты (что меняется / что нет).
   Дельта дизайна — только если меняется обещание механики/UX.
   Новые неблокерные вопросы — `assumptions.md`.
   Блокеры — задать, потолок 5–7. Пока открыты — кода нет.
   Диаграммы — только если дельта меняет границу или порядок.
   Полный набор не перерисовывать.

4. **Критик.**
   Нужен, если дельта меняет обещание, допущения или user path.
   Не нужен, если дельта — явная реализация уже принятого пункта спеки
   и новых допущений нет. Критик — новый контекст.

5. **Реализация.**
   Код + живые доки + тесты на дельту. Playtest — затронутые пути.
   `test-report.md` с пометкой «increment, гоняли X». Draft → PR.

6. **Ревью.**
   Как [../review.md](../review.md). Первый проход по дельте.
   Выход — ноль блокеров. >5 итераций → человек.

7. **Фиксы.**
   Implementer закрывает. Ревьюер не открывает вкус. Merge по protection.

8. **Release не включать.**
   Поставка — [release.md](release.md) по просьбе.

## Артефакты

Обязательны: дельта спеки (или явная строка «контракт не меняется,
пункт N»), `test-report.md`, `review.md`, PR.
Не обязательны: новый C4, полный дизайн-альбом, `release.md`.

## Чего не делать

- Не переписывать соседние разделы спеки «раз уж открыл».
- Не расширять контур до новой фичи внутри increment.
- Не пропускать ревью, потому что «маленькое».
