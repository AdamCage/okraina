# AGENTS.md — процесс

Общий SDLC для ИИ-агентов в любом игровом продукте, куда подключён
канон как `<sdlc-root>`. Домен (как писать игру, как менять этот канон)
процесс не заменяет. Процесс домен не заменяет.

Читать вместе с [SKILL.md](SKILL.md). Класс задачи — сначала
[workflows/router.md](workflows/router.md), затем один рецепт.

Если этот файл расходится с корневым `AGENTS.md` репозитория-потребителя,
побеждает корневой в своих hard invariants.

## Когда применять

Любая работа в репозитории, который объявил этот process.
Не применять к правке канона «в голове» без файлов: изменение
`<sdlc-root>` — домен [../evolve/](../evolve/), но класс задачи
всё равно отсюда.

## Порядок чтения

1. Корневой `AGENTS.md` потребителя (или [../AGENTS.md](../AGENTS.md),
   если работаем в этом репозитории).
2. Этот файл.
3. [workflows/router.md](workflows/router.md) — один класс.
4. Рецепт класса и роли, которые он зовёт.
5. `AGENTS.md` затронутого домена и строка из его `SKILL.md`.
6. Координация в GitHub — [github.md](github.md), если задача
   заводит Issue/PR/label/milestone/release.

Не читать все reference-файлы сразу.

## Hard invariants

1. Сначала класс задачи (router), затем один рецепт. Не гонять
   `feature-cycle` на опечатку. Не пропускать спеку на новом контуре.
2. Контракт — `spec.md` и `assumptions.md`, не чат. Для игрового
   контура живой дизайн-пакет домена — рядом со спекой, не вместо неё.
3. Нет реализации, пока открыты аналитические блокеры, если человек
   не принял допущения.
4. Ревьюер не чинит тот же diff. Свежий контекст субагента. Выход
   только при нуле блокеров.
5. Вкус и ниты не блокируют после первого прохода ревью. Дальше —
   открытые пункты и регрессия.
6. После 5 итераций ревью — к человеку с дедлоком, не с дампом нитов.
7. Спросить до деструктивных действий (прод-store, force-push,
   отзыв билда, wipe сохранений игроков, массовый rerun CI).
8. Тесты — выход работы. Пирамида зависит от класса. Hotfix ≠ полный
   playtest-пакет фичи.
9. Домен не заменяет процесс. Процесс не заменяет домен.
10. Новый домен не изобретает второй SDLC. Тот же набор файлов, что у
    [../game/](../game/).
11. GitHub — система учёта и координации: Issue ↔ контур, PR ↔ diff,
    labels/milestones ↔ класс и стадия, Actions ↔ проверки,
    Release/tag ↔ поставка. Не вести контракт только в чате.

«Отдельный субагент» = новый контекст, не смена тона в том же чате.

## Конфликт слоёв

[specialize.md](specialize.md). Кратко:

1. Корневой `AGENTS.md` потребителя — объявленные hard invariants.
2. Проектный `<domain>/AGENTS.md` — пути, имена, локальные инварианты.
3. `<sdlc-root>/process` — процесс, пока стадия не выключена.
4. `<sdlc-root>/<domain>` — стиль и раскладка домена, пока принцип
   не переопределён явно.

Не копировать канон в проектные файлы. Ссылаться.
В текстах путь всегда `<sdlc-root>`.
