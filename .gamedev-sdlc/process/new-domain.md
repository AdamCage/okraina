# Новый предметный домен

Домен отвечает на «как производить работу *здесь*», не на «как
вообще работают агенты». Процесс уже есть: роли, router, гейты,
эскалация, GitHub. Домен их не пересказывает.

## Форма

Тот же набор файлов, что у [../game/](../game/):

| Файл | Зачем |
|---|---|
| `AGENTS.md` | Когда применять / когда нет, hard invariants домена |
| `SKILL.md` | Таблица «задача → что читать» |
| `principles.md` | Зачем инварианты |
| `specialize.md` | Как сузить под продукт |
| `workflows.md` (или каталог рецептов) | Как сделать шаг *в этом* домене |
| `review.md` | Чеклист ревью доменного diff-а |
| `style.md`, `layout.md` (или аналоги) | Стиль и раскладка, если есть смысл |
| `templates/` | Пустые заготовки проектного слоя |

Каркас: [../evolve/templates/domain/](../evolve/templates/domain/).

Каталог домена — **корень** `<sdlc-root>/`, рядом с `game/`.
Не `process/<domain>/`. Не `domains/<domain>/`.

## Чего в домене нет

- Второго router и второго набора ролей.
- Своей эскалации «после N ревью» — это process.
- Копии process-принципов.
- Продуктовых имён (конкретная игра, bundle id, store listing).

Домен ссылается на `<sdlc-root>/process/...` там, где начинается цикл.

## Куда класть в продукте vs в канон

| Ситуация | Куда |
|---|---|
| Факты верны только для этого репозитория | Тонкая проектная обвязка: `<domain>/AGENTS.md` в продукте, ссылка на ближайший канон-домен или на process |
| Подход переиспользуется в следующем проекте | Черновик формы game с пометкой «кандидат в канон» в продукте; подъём — [../evolve/workflows.md](../evolve/workflows.md) |
| Уже верно для следующего проекта | Домен в этот репозиторий, класс `feature-cycle` + evolve-рецепт `new-domain` |

Не плодить домен «на всякий случай». Сначала проект-локально.

## Как агент заводит домен в каноне

1. Класс — `feature-cycle` (новый подход к производству работы).
2. Рецепт — [../evolve/workflows.md](../evolve/workflows.md) (`new-domain`).
3. Спека: когда применять / когда нет, инварианты, таблица SKILL,
   как стыкуется с router (какие классы зовут домен).
4. Не писать второй SDLC. После мержа — строка в [../README.md](../README.md)
   и в [workflows/bootstrap-project.md](workflows/bootstrap-project.md).
5. Issue/PR в GitHub этого репо по [github.md](github.md).

## Стык с процессом

Новый игровой контур / новая механика в известном домене — сначала
класс process (`feature-cycle` или `increment`), потом рецепты домена.
Красный билд / краш — `hotfix` или `incident`, потом доменный debug.
Ревью доменного diff-а — `review-only` + `<domain>/review.md`.
